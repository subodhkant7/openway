# OpenWay Evidence & Observation Model

## Architectural Principle

> **Ring is evidence infrastructure.**

Ring devices, webhook notifications, snapshots, and media clips supply raw physical telemetry. Ring integration layers do not contain accessibility business policy. The OpenWay domain layer translates physical evidence into verified entrance states.

---

## Provider-Neutral Evidence Model

OpenWay abstracts physical observations into a provider-neutral `Evidence` entity.

### Schema

```typescript
export interface Evidence {
  id: string;
  venueId: string;
  entranceId: string;
  provider: "RING" | "SIMULATOR" | "OPENWAY";
  providerEventId?: string;
  deviceId: string;
  componentId: string;
  capturedAt: string;     // ISO 8601 timestamp when Ring camera captured the media
  receivedAt: string;     // ISO 8601 timestamp when OpenWay ingested the payload
  evidenceType: "IMAGE" | "VIDEO" | "EVENT" | "STATUS";
  mediaReference?: string;
  provenance: "OFFICIAL_RING" | "SIMULATED_LOCAL" | "OPENWAY_DERIVED";
  isSimulated: boolean;
  freshness: "FRESH" | "STALE" | "INVALID" | "UNKNOWN";
  checksum?: string;
  createdAt: string;
}
```

---

## Strict Provenance Tracking

OpenWay enforces an uncompromised provenance boundary:

1. `OFFICIAL_RING`: Evidence retrieved directly via official Amazon Ring Partner API endpoints or verified via HMAC-SHA256 signed webhooks (`X-Signature`).
2. `SIMULATED_LOCAL`: Locally generated synthetic evidence from the deterministic simulator or Developer Playground workbench.
3. `OPENWAY_DERIVED`: Derived metadata or composite evidence generated by the OpenWay processing pipeline.

**Security Rule**: A simulated image or synthetic event must **never** masquerade as official Ring evidence (`isSimulated: true && provenance: "OFFICIAL_RING"` is rejected by the gatekeeper as `INVALID_PROVENANCE`).

---

## Deterministic Freshness Evaluator

Freshness is evaluated deterministically without relying on AI confidence scores or external clocks.

### Evaluation Rules

- **Timestamp Basis**: Freshness is strictly calculated from `capturedAt` (the camera capture moment), not merely `receivedAt` or database insertion time.
- **Clock Drift Tolerance**: Future timestamps exceeding 15 seconds are classified as `INVALID`.
- **Configurable Thresholds**:
  - Image snapshots: 180 seconds (3 minutes) default.
  - Video clips: 300 seconds (5 minutes) default.
  - Webhook events: 60 seconds (1 minute) default.
  - Device health status: 120 seconds (2 minutes) default.
- **Outcomes**:
  - `FRESH`: Age &le; configured threshold and within clock tolerance.
  - `STALE`: Age &gt; configured threshold.
  - `INVALID`: Unparseable date or future timestamp beyond tolerance.
  - `UNKNOWN`: Missing timestamp or corrupted payload.

## Structured Observation Model (Tri-State)

Observations generated by vision analyzers or rule engines use an explicit tri-state representation to prevent JavaScript nullable boolean ambiguities:

```typescript
export type ObservationValue = "TRUE" | "FALSE" | "UNKNOWN";

export interface AccessibilityObservation {
  id: string;
  evidenceId: string;
  entranceId: string;
  pathwayClear: ObservationValue;
  obstructionPresent: ObservationValue;
  doorReady: ObservationValue;
  confidence: number; // 0.0 - 1.0 (statistical quality metric, not state decision)
  observedAt: string;
  analyzer: string;
  analyzerVersion: string;
  explanation: string;
}

export interface DetailedVisionObservation extends AccessibilityObservation {
  evidenceQuality: "SUFFICIENT" | "INSUFFICIENT";
  observedFeatures: string[];
  modelId?: string;
  modelRegion?: string;
  isSimulated: boolean;
  timingMs?: {
    totalMs: number;
    inferenceMs?: number;
  };
}
```

### Phase 3 Bedrock Integration Details

For observations produced by Amazon Bedrock:
* `analyzer`: `"amazon-bedrock"`
* `modelId`: `"amazon.nova-lite-v1:0"` (or configured ID)
* `modelRegion`: e.g. `"us-east-1"`
* `isSimulated`: dynamically tracks whether the source Ring evidence was `SIMULATED_LOCAL` vs `OFFICIAL_RING`.
* `evidenceQuality`: deterministic gate (`SUFFICIENT` vs `INSUFFICIENT`). If lighting is too dark, glare blinds the sensor, or the entrance is occluded, `evidenceQuality = "INSUFFICIENT"` and conditions resolve to `"UNKNOWN"`.

## Observation Aggregation Matrix

When multiple observations and evidence items are submitted for an entrance, the deterministic aggregator evaluates them according to explicit rules:

| Case | Evidence & Observations | Aggregation Outcome | Reason Code |
| :--- | :--- | :--- | :--- |
| **Case A** | `pathwayClear = TRUE`, `obstructionPresent = FALSE`, `doorReady = TRUE`, all evidence fresh | `SATISFIED` | `REQUIREMENTS_SATISFIED` |
| **Case B** | `obstructionPresent = TRUE` or `pathwayClear = FALSE` | `INTERRUPTED` | `ACCESS_INTERRUPTED` |
| **Case C** | `obstructionPresent = FALSE`, but evidence capturedAt &gt; maxAge | `UNKNOWN` | `STALE_EVIDENCE` |
| **Case D** | Conflicting fresh observations (e.g. Analyzer A: `TRUE`, Analyzer B: `FALSE`) | `UNKNOWN` | `CONTRADICTORY_OBSERVATIONS` |
| **Case E** | Evidence deviceId does not match entrance camera binding | `UNKNOWN` / `REJECTED` | `NO_MATCHING_EVIDENCE` |

## Explicit Camera Binding

An entrance is explicitly bound to a specific Ring device and component:

```typescript
export interface CameraBinding {
  deviceId: string;       // e.g. "cam_front_entrance"
  componentId: string;    // e.g. "component_video_01"
  deviceName?: string;
  notes?: string;
}
```

Evidence from an unassociated camera (e.g. a rear loading dock camera) will **never** restore an entrance ramp, preventing cross-camera false verifications.
